# 项目章程

## 背景

现有博客已经具备 Astro 静态生成、内容集合、Swup/Astro 浏览器交互、GitLab 内容同步、生产评论服务和 Cloudflare 发布能力。当前主要结构性问题集中在：

- Obsidian CI 通过 `rsync --delete` 将 `Blog/` 写入目标仓库并直接提交、推送，内容提交与应用提交身份混合；
- 构建版本无法同时精确关联应用代码与内容提交；
- Obsidian Markdown 方言缺少独立、可测试的标准化层；
- BlogService 聚合了读取、规范化、slug、排序、缓存与 selector；
- 浏览器脚本存在多事件源和重复初始化风险；
- 当前生产评论前端、Worker、D1、OAuth、域名与 CI 配置需要按已批准决定完整退役；
- 发布、测试、资产完整性和运行观测尚未形成统一门禁。

## 总目标

将博客改造成一个模块化单体，并以两个 Git 仓库、一个确定性内容编译器和一个原子部署单元完成交付。

## 成功指标

- 所有现有文章 URL 保持稳定，任何变化均有显式 redirect 清单。
- 同一个应用 SHA、内容 SHA 和 lockfile 可生成相同路由清单与内容清单。
- 内容构建不再通过向 Astro 仓库提交同步副本来触发，能够由 app/content 双 SHA 直接复现。
- Obsidian 的公开内容错误在部署前失败，并给出文件、行号和修复建议。
- `src/pages/**` 只做路由和组件装配。
- 模块内部实现不被跨模块深层引用。
- 浏览器连续导航 20 次后，监听器、Observer 和网络请求数量保持有界。
- Cloudflare 发布支持 staging、dry-run、生产部署和版本回滚。
- 生产与代码仓库中评论 UI、脚本、环境变量、Worker、D1、OAuth、secret、DNS 和预留适配器均完成零残留核验。

## 明确排除

- 本轮只退役现有评论能力，不设计或实现下一代评论系统；未来需求必须新建 OpenSpec change。
- 本轮不同时进行视觉大改。
- 本轮不强制升级 Astro 主版本。
- 本轮不实现完整 Obsidian Canvas、Dataview 查询或任意插件语法。
- 本轮不将内容改造成运行时 CMS。
